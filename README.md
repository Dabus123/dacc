# CONTRIBUTING TO d/acc

> **don't ask for permission. contribute signal.**

d/acc is an open network for people building the infrastructure, protocols, agents, markets, and ideas behind **decentralized intelligence**.

You don't need an invitation.

You don't need a title.

**If you're building, researching, documenting, testing, connecting, or thinking — you can contribute.**

---

## WHAT COUNTS AS A CONTRIBUTION?

Pretty much anything that moves the ecosystem forward.

### `BUILD`

Ship code.

* autonomous agents
* agent frameworks
* wallets & identity
* payment rails
* coordination protocols
* onchain infrastructure
* agent-to-agent communication
* AI × crypto primitives
* developer tooling

### `RESEARCH`

Push the ideas forward.

* papers
* experiments
* technical writeups
* protocol research
* economic mechanisms
* security research
* new agent architectures

### `DISCOVER`

Help map the ecosystem.

* submit projects
* find emerging protocols
* document useful tools
* maintain ecosystem lists
* surface interesting experiments

### `WRITE`

Turn complexity into signal.

* explainers
* tutorials
* documentation
* essays
* project profiles
* research summaries
* field notes

### `CONNECT`

Bring people together.

* introduce builders
* organize meetups
* start working groups
* collaborate across projects
* share opportunities

### `BREAK`

Find what doesn't work.

* report bugs
* identify security issues
* challenge assumptions
* reproduce failures
* question bad designs

**Good criticism is contribution.**

---

## THE RULE

Before opening an issue or PR, ask:

> **Does this increase the amount of useful information, infrastructure, or coordination available to the network?**

If yes, ship it.

---

## HOW TO CONTRIBUTE

### 1. Find something

Browse the repository and existing issues.

Look for:

```text
good first issue
help wanted
research
infrastructure
documentation
ecosystem
```

Or find something nobody has written down yet.

### 2. Open an issue

For substantial work, start a discussion first.

Tell us:

```text
what are you building?
why does it matter?
what exists already?
what are you proposing?
how can others contribute?
```

Don't write a novel.

**Signal > ceremony.**

### 3. Fork → build → submit

For code or documentation:

```bash
git clone <repo>
cd <repo>

# make your change

git checkout -b your-contribution
git commit -m "describe what changed"
git push origin your-contribution
```

Then open a pull request.

Explain **what changed and why**.

---

## PR PRINCIPLES

Keep contributions:

* focused
* understandable
* reproducible
* technically honest
* easy to review

Small PRs are easier to merge.

Large ideas are welcome.

**Large diffs without a clear reason are not.**

## SECURITY

If you find a vulnerability, **do not publish exploitable details immediately**.

Contact the maintainers privately first and give the project a reasonable opportunity to investigate and fix the issue.

Responsible disclosure protects builders and users.

---

## CYBERPUNK ETIQUETTE

d/acc is permissionless, but it is not lawless.

### DO

* verify before repeating
* cite your sources
* share useful information
* challenge ideas, not people
* disclose conflicts
* give credit
* build in public
* assume good faith
* preserve user sovereignty

### DON'T

* spam
* manipulate metrics
* impersonate projects
* manufacture consensus
* plagiarize
* hide material conflicts
* submit undisclosed malicious code
* turn the repository into an advertising feed

**Open networks require strong norms.**

---

## LICENSE YOUR WORK

When possible, make contributions reusable.

Open source is infrastructure.

If you're unsure which license fits your contribution, ask in an issue before publishing.
